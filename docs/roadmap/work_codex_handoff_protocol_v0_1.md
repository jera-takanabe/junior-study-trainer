# Work・Codex受け渡し手順 v0.1

## 1. 文書の目的

Junior Study Trainer完成版再開発における、
PC版ChatGPT Work、VS CodeのCodex、ユーザーの3者間の
作業受け渡し方法を統一する。

各作業を一つの明確な単位に限定し、
調査、編集、検証、レビュー、commit、pushの責任を明確にする。
新しいWorkタスクへ切り替えた後も、
正式資料と完了報告から作業を再開できる情報を残し、
ブラウザチャットの履歴だけに依存しない運用とする。

## 2. 適用範囲

- Junior Study Trainer完成版再開発における、
  Work、VS CodeのCodex、ユーザー間の作業受け渡しに適用する。
- 当面の作業環境整備、調査、限定的な文書編集、検証に適用する。
- 設計内容、技術選定、完成版実装そのものを定める文書ではない。

## 3. 基本原則

- 1回の依頼につき、一つの明確な作業だけを扱う。
- Codexは指定範囲外を変更しない。
- 要求内容と設計判断を混同しない。
- 正式資料は `docs/` 配下を参照する。
- `.local/` 配下は正式資料や通常の引き継ぎ根拠にしない。
- 通常条件をすべて満たし、Workまたはユーザーの指示に
  「Git反映まで許可」と明記されている場合だけ、
  Codexは指定ファイルのstage、commit、
  指定先への通常pushを実行できる。
- Git反映の許可が明記されていない場合、
  CodexはGit書き込み操作を行わない。
- ユーザーは通常作業でGitコマンドを実行せず、
  重要判断と例外承認を担当する。
- 通常条件を満たさない場合、
  Codexは独断でGit反映へ進まない。
- 未許容の警告がある場合はGit反映へ進まない。
- 正式に定義されたLF→CRLF警告は、
  全許容条件を満たす場合だけ継続できる。
- 未決事項や想定外の状態を推測で固定しない。

## 4. 3者の責任

### 4.1 PC版ChatGPT Work

Workは次を担当する。

- 次に行う一作業の決定
- Codex向け指示の作成
- Git反映可否の明示
- 期待する開始ブランチの明示
- commit対象の明示
- stage禁止対象の明示
- commitメッセージの明示
- push先の明示
- 必須検証と停止条件の明示
- 工程管理、方針検討、要求定義成果物の参照、
  要求IDとの対応確認および重要判断
- Codexから返された完了報告の事後レビュー
- 例外時にユーザー承認が必要かの判断

Workは、開始時点では完成版コードの広範囲な直接編集を
主担当としない。Gitコマンドを自動実行しない。

### 4.2 VS CodeのCodex

Codexは次を担当する。

- 作業開始前のGit状態確認
- 指定された一作業だけの調査・編集
- 指定された検証
- 差分の自己確認
- Git反映条件の判定と再判定
- 明示的に許可され、通常条件をすべて満たす場合だけ、
  指定ファイルのstage、commit、通常pushを実行
- staged diffの確認
- push後のGit状態確認
- Git反映結果を含む完了報告
- 停止条件に該当した場合の報告と停止

Codexは、Workまたはユーザーから指定された一作業だけを行う。
設計方針、要求の削除・統合、技術選定を独断で確定しない。

### 4.3 ユーザー

ユーザーは次を担当する。

- 重要な設計判断の承認
- 大規模、破壊的、例外的な操作の承認
- 運用変更の承認
- 例外時の最終判断
- 通常条件を満たす作業ではGitコマンドを実行しない
- WorkとCodex間の指示・結果の受け渡し
- Workタスク切替時の引き継ぎ管理

## 5. 作業区分

### 5.1 調査のみ

- ファイル変更を行わない。
- 読み取り、検索、状態確認、結果報告だけを行う。
- Git状態や差分の読み取り確認だけを許可する。
- 完了報告では、変更がないことを明記する。

### 5.2 編集あり・Git反映なし

- 指定されたファイルだけを変更する。
- 編集前に対象ファイルと変更目的を確認する。
- 指定された検証と差分確認まで行う。
- `git add`、commit、pushは行わない。

### 5.3 編集あり・条件付きGit反映あり

- 指示に「Git反映まで許可」が明記されている。
- `AGENTS.md` と本手順の通常条件をすべて満たす場合だけ、
  指定ファイルのstage、commit、通常pushを実行する。
- 条件を満たさない場合はGit反映へ進まず停止する。

### 5.4 例外承認が必要な作業

- 通常条件を外れる作業
- 大規模、破壊的、横断的な作業
- 重要な要求・設計判断を伴う作業
- 常時禁止操作または通常外のGit操作が必要となる作業

Codexは例外承認が必要な作業を独断で実行しない。
常時禁止操作が必要になった場合は停止し、
ユーザーが別作業として実施方法または代替手段を判断する。
ユーザーの承認は、Codexによる常時禁止操作の
実行許可を意味しない。

### 5.5 Git反映を許可できる条件

Codexがstage、commit、通常pushを実行できるのは、
次をすべて満たす場合だけとする。

- Workまたはユーザーの指示に「Git反映まで許可」と明記されている。
- 変更対象ファイルが明確である。
- commit対象ファイルが明確である。
- commitメッセージが明確である。
- push先のリモートとブランチが明確である。
- 作業開始前の作業ツリーがクリーンである。
- 変更が指定範囲内だけである。
- ファイルの削除、移動、名称変更を含まない。
- 指定された検証がすべて成功している。
- 未許容の警告、未解決事項、判断待ちがない。
- 許容対象のLF→CRLF警告がある場合は、
  以下の全許容条件を満たし、完了報告へ記録する。
- 秘密情報、認証情報、非公開教材を含まない。
- 要求、重要な設計判断、公開API、データベース構造、
  依存関係へ影響しない。
- 明示されたファイルだけをstageする。
- staged diffが指示内容と一致している。

#### LF→CRLF警告の限定許容

次の意味と形式に一致する警告だけを許容候補とする。

`LF will be replaced by CRLF the next time Git touches it`

警告対象ファイル名や前後の定型文を含む場合も、
LFからCRLFへの変換予告という意味が一致する場合だけを対象とする。

許容できるのは、次をすべて満たす場合だけとする。

- 警告文が上記の許容対象と一致する。
- 警告対象が、明示された変更対象またはcommit対象だけである。
- `git diff --check` の終了コードが0である。
- 通常差分が指示内容だけである。
- `git diff --numstat` 等で確認した差分件数に、
  想定外の大量変更がない。
- ファイル全体が改行変更として差分化されていない。
- 対象外ファイルの変更および未追跡ファイルがない。
- `git check-attr` 等で対象ファイルに
  矛盾する改行属性がない。
- `.gitattributes` 等の明示的な改行方針と矛盾しない。
- Gitの改行関連設定を確認し、警告原因を説明できる。
- stage後のstaged diffと差分件数が指示内容どおりである。
- stage前後で実質的な差分内容が変化していない。
- 対象外のstaged変更およびunstaged変更がない。
- この警告以外のエラー、警告、未解決事項、
  判断待ちがない。
- 完了報告へ警告全文、対象ファイル、
  各確認結果および許容判断を記録する。

`git diff --check` の終了コードが0という理由だけ、
または警告が既知という理由だけでは許容しない。
CRLFからLFへの変換、その他の改行、文字コード、
バイナリ判定、safecrlf等の警告は許容対象に含めない。
原因を確認または説明できない警告、指定範囲外の警告、
その他すべての警告も許容対象に含めない。

### 5.6 commitまたはpush前の停止条件

次のいずれかに該当する場合、Codexはcommitまたはpushへ進まず、
停止段階と理由を報告して、Workまたはユーザーへ判断を求める。

- 作業開始前から既存変更または未追跡ファイルがある。
- 現在のブランチが指示と一致しない。
- push先が指示と一致しない。
- ahead／behindや分岐が想定外である。
- 対象外変更がある。
- 変更が複数領域へ広がった。
- ファイルの削除、移動、名称変更が必要になった。
- 差分が想定より大きい。
- 要求、重要な設計、公開API、データベース構造、
  依存関係へ影響する。
- 検証失敗、許容条件をすべて満たすLF→CRLF警告以外の警告、
  未確認事項、未解決事項、判断待ちがある。
- LF→CRLF警告の許容条件を一つでも確認できない。
- 警告原因を確認または説明できない。
- 警告対象が指定範囲外である、または複数ファイルへ
  想定外に警告が出ている。
- 許容対象の警告と別の警告が同時に出ている。
- stage前後で実質的な差分内容が変化している。
- ファイル全体の改行変更が差分に現れている。
- Git属性または明示的な改行方針と矛盾している。
- staged diffまたは差分件数が指示内容と一致しない。
- 秘密情報、認証情報、非公開教材を含む可能性がある。
- staged diffが指示されたcommit対象と一致しない。
- pushが非fast-forwardなど通常外の操作を要求する。
- 通常条件を満たしていると確認できない。

### 5.7 常に禁止するGit操作

Codexは、Git反映の許可の有無にかかわらず、
次を実行してはならない。

- force push
- force-with-lease
- rebase
- commit amend
- resetによる変更またはcommitの破棄
- `git clean`
- checkout、restoreなどによる既存変更の破棄
- ブランチの作成
- ブランチの削除
- マージ
- タグの作成、変更、削除、push
- 指示されていないブランチへの切替
- 競合の独断解決
- 既存変更を含む一括stage
- 指示されていないリモートまたはブランチへのpush

常時禁止操作が必要になった場合、Codexは停止する。
ユーザーが承認してもCodexの実行許可とはならず、
ユーザーが別作業として実施方法または代替手段を判断する。

条件付きGit反映でCodexに許可されるGit操作は、
明示されたファイルのstage、commit、
指定先への通常pushだけとする。

## 6. 標準フロー

1. Workが次の一作業を決定する。
2. WorkがGit反映の可否、開始ブランチ、commit対象、
   stage禁止対象、commitメッセージ、push先、
   検証、停止条件を明示する。
3. ユーザーが必要な重要判断を承認し、Codexへ指示を渡す。
4. Codexが適用される指示ファイルと正式資料を確認する。
5. Codexが作業開始前のGit状態を確認する。
6. Codexが通常条件を満たすか確認する。
7. Codexが指定範囲内で調査・編集する。
8. Codexが指定された検証を実行する。
9. Codexが差分を自己確認する。
10. CodexがGit反映条件を再判定する。
11. 条件を満たす場合、
    Codexが明示されたファイルだけをstageする。
12. Codexがstaged diffを確認する。
13. Codexが指定されたメッセージでcommitする。
14. Codexが指定されたリモート・ブランチへ通常pushする。
15. Codexがpush後のGit状態を確認する。
16. CodexがWorkへ完了報告を返す。
17. Workが事後レビューする。
18. 問題がある場合は履歴を書き換えず、
    別の一作業・別のcommitで修正する。

停止条件に該当した場合はGit反映へ進まず、
Workまたはユーザーの承認待ちとする。

Git反映なしの作業では、差分と検証結果を報告した後、
Workがレビューする。

## 7. WorkからCodexへ渡す指示の必須項目

WorkからCodexへ渡す指示には、少なくとも次を含める。

- 作業名
- 作業目的
- 作業区分
- 最初に読む資料
- 変更対象
- 変更してはいけない対象
- 実施内容
- 実施してはいけない内容
- 要求IDまたは根拠資料
- 完了条件
- 検証方法
- 完了報告の形式
- Git反映まで許可するか
- 期待する開始ブランチ
- 許可するGit読み取り操作
- commit対象
- stage禁止対象
- commitメッセージ
- push先のリモートとブランチ
- 必須検証
- commit前の停止条件
- push前の停止条件
- push失敗時の扱い
- 常時禁止操作
- 判断が必要になった場合の停止条件
- 許容可能な既知警告があるか
- 許容する警告の正確な形式
- 警告対象として許容するファイル
- 確認すべき全許容条件
- 許容条件不成立時の停止条件
- stage前後で行う差分確認
- 許容した警告に関する完了報告項目

明示的な許可と通常条件がある場合だけ、
Codexは指定範囲のGit反映を行える。
許可がない場合はGit書き込み操作を行わず、
常時禁止操作は許可の有無にかかわらず実行しない。
許容警告が指示に明示されていない場合は、
警告がある状態でGit反映へ進まず停止する。

対象ファイル、変更目的、許可する操作、禁止する操作が
曖昧な場合、Codexは推測で作業範囲を広げず、
確認するか作業を停止する。

## 8. CodexからWorkへ返す報告の必須項目

CodexからWorkへ返す報告には、少なくとも次を含める。

- 実施した作業
- 参照した資料
- 変更したファイル
- 変更していない対象
- 変更内容の要約
- 実行した検証
- 検証結果
- エラーや警告
- 未解決事項
- 判断が必要な事項
- 想定外に発見した既存変更
- 作業開始前のGit状態
- stageしたファイル
- staged diffの確認結果
- commit ID
- commitメッセージ
- push先
- push結果
- push後のGit状態
- 停止した場合の停止段階
- 常時禁止操作を行っていないこと
- Git反映を行わなかった場合は、
  Git書き込み操作を行っていないこと

LF→CRLF警告を許容した場合は、さらに次を含める。

- 警告全文
- 警告対象ファイル
- 警告が表示された操作または確認
- `git diff --check` の終了コードと結果
- stage前およびstage後の差分件数
- 通常差分およびstaged diffの確認結果
- Git属性および `.gitattributes` 等の
  明示的な改行方針の確認結果
- Gitの改行関連設定と警告原因の説明
- stage前後で実質的な差分内容が一致していること
- 許容判断の根拠
- 許容対象以外の警告がなかったこと

変更がない場合も、その旨を明記する。
Git反映を行わなかった場合は、
Git反映なしで完了したのか、
停止条件により中断したのかを区別して報告する。

## 9. 差分レビューと承認

- Codexは編集後、対象ファイルの差分と作業ツリー状態を確認する。
- Codexは指定範囲外の変更を自分の変更として扱わない。
- Codexは既存変更と今回の変更を区別して報告する。
- 通常条件を満たし、Git反映が明示的に許可されている場合、
  Codexが差分自己確認、stage、commit、通常pushを行い、
  Workが事後レビューする。
- 例外条件や停止条件に該当した場合、
  Codexはcommitまたはpush前に停止する。
- commit後にpushだけ失敗した場合は、
  commit済み・push未完了として報告し、判断を待つ。
- Workは目的、要求、対象範囲、差分、
  検証結果およびGit反映結果の整合性を確認する。
- 許容警告がある場合も、Codexはstage前後の差分を自己確認し、
  Workは事後レビューで許容条件と報告内容を確認する。
- 警告許容と改行変換の実施を同一視しない。
- 承認とGitコマンドの手動実行を同一視しない。

ユーザー承認を必要とする重要判断は、少なくとも次とする。

- 重要な要求または設計判断
- 大規模、横断的、破壊的な変更
- ファイル削除、移動、名称変更
- 公開API、データベース構造、依存関係への重要な影響
- 秘密情報、認証情報、非公開教材に関する判断
- ブランチ、タグ、履歴、競合に関する通常外操作
- 運用ルールの変更

## 10. Workタスク切替時の引き継ぎ情報

新しいWorkタスクでも作業を再開できるよう、
少なくとも次の情報を残す。

- プロジェクト名
- 現在の工程
- 作業目的
- 完了済みの作業
- 進行中または次に行う一作業
- 参照すべき正式資料
- 対象となる要求ID
- 変更済みファイル
- 差分の状態
- 検証内容と結果
- 未解決事項と判断待ち事項
- Git反映の有無
- 作業ツリーに既存変更がある場合の情報
- 引き継ぎ情報を記録した場所
- 最後に確認したGit状態
  （ブランチ、リモートとの関係、作業ツリーの変更、
  既存変更の有無）
- commit ID
- commitメッセージ
- push先
- push結果
- push後のGit状態
- Git反映を行ったか
- 例外承認待ちの有無
- 停止段階
- commit済み・push未完了などの状態
- 禁止事項および次の作業開始条件

チャット本文だけに情報を残さず、
必要な正式な判断結果は `docs/` 配下の適切な成果物へ反映する。
反映先の文書は、個別作業の指示で明示する。

## 11. 異常時・中断時・想定外変更発生時の扱い

- エラーや検証失敗を隠さず報告する。
- 指定範囲外の変更が必要になった場合は、
  変更せず停止して判断を求める。
- 作業開始前から存在する変更を勝手に修正、削除、破棄しない。
- 想定外の変更を発見した場合は、
  対象、状態、今回の作業との関係を報告する。
- 指示間の矛盾や適用範囲の不明点がある場合は、
  推測で進めない。
- 中断時も、実施済み内容、未実施内容、
  変更状態、検証状態を報告する。
- 作業が長時間化した場合、当初の想定より作業範囲が広がった場合、
  または指定された一作業として安全に完了できない場合は、
  Codexは途中経過を報告して停止できる。
- この停止報告には、途中経過、完了済みの内容、未実施の内容、
  現在の変更状態、現在の検証状態、停止理由、
  継続に必要な判断を含める。
- 停止時は対象範囲を独断で拡大せず、
  未実施部分を完了したものとして報告しない。
- commit後にpushだけ失敗した場合は、
  commit済み・push未完了として報告する。
- push失敗をamend、reset、rebase、force pushなどで
  独断解決しない。
- 中断時は、commit前、commit後、push前、
  push後のどの段階かを明示する。
- stage済みでcommit前に停止した場合は、その状態を報告する。
- stage後に警告の許容条件を満たさなくなった場合は、
  commitせず、stage状態を独断で変更せずに報告する。
- stage前後で差分が変化した場合は、その状態を報告する。
- 警告を消すための設定変更や改行変換を行わない。
- 通常条件を満たせなくなった場合は、
  対象範囲を拡大せず停止する。
- 問題の修正は履歴を書き換えず、
  承認された別作業・別commitで行う。
- 破壊的操作、ファイル削除、移動、一括置換は、
  明示的な許可なしに行わない。
- 作業を安全に継続できない場合は、その理由を示して停止する。

## 12. 禁止事項

- 一つの指示で複数の大きな作業を進めること
- 指定範囲外のファイル変更
- 要求の独断による削除、統合、弱体化
- 未決事項の黙示的な確定
- 設計方針や技術選定の独断による確定
- プロトタイプを完成版の既定構造として採用すること
- `.local/` 配下を正式資料として扱うこと
- 非公開教材を公開リポジトリへ追加すること
- 検証結果やエラーを省略すること
- 既存変更を勝手に破棄すること
- Git反映の許可がない状態で、
  Codexがstage、commit、pushを行うこと
- 通常条件を満たさない状態でGit反映へ進むこと
- force push、force-with-lease、rebase、commit amend
- reset、`git clean`、checkout、restoreによる変更破棄
- ブランチの作成・削除、マージ
- タグの作成・変更・削除・push
- 指示されていないブランチへの切替
- 競合の独断解決
- 既存変更を含む一括stage
- 指示されていないリモートまたはブランチへのpush
- 警告が既知という理由だけで無条件に許容すること
- `git diff --check` の終了コードが0という理由だけで
  警告を許容すること
- 警告原因を推測だけで固定すること
- 改行変換を独断で実施すること
- `.gitattributes` を独断で作成または変更すること
- Gitの改行設定を独断で変更すること
- 対象ファイル全体の改行形式を独断で変更すること
- 警告を消す目的で対象外ファイルや設定を変更すること
- stage前後の差分確認を省略すること
- 許容対象以外の警告を同じ例外へ含めること

通常条件をすべて満たし、Git反映が明示的に許可された場合だけ、
Codexは指定範囲のstage、commit、通常pushを実行できる。

## 13. 運用ルールの見直し

今回の文書更新だけでは、新運用を開始しない。
更新後の本書と `AGENTS.md` の整合性確認が完了するまでは、
Codexによる `git add`、commit、pushを行わない。

整合性確認後、小規模かつ低リスクな試験から新運用を開始する。
試験結果をWorkが事後レビューし、
必要な修正は別作業で行う。
この開始条件は、文書内の条件付きGit許可より優先する。

- この手順は開始時点の運用ルールである。
- 試行結果、問題発生、工程の進展、
  責任分界の変更が必要になった場合に見直すことができる。
- 見直しはWorkまたはユーザーが提案し、ユーザーが承認する。
- Codexは独断で運用ルールを変更しない。
- 変更理由、影響範囲、変更内容を記録し、版番号を更新する。
- 見直し後も、要求追跡、正式資料の優先、1回1作業、
  Git操作の責任分界を維持するか明示的に判断する。
